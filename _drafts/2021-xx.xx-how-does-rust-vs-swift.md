# XCFramework for a static Swift library

Recently I've been diving more into libraries, frameworks, linkage type, and so on..

One of the interesting things about [XCFramework](https://developer.apple.com/videos/play/wwdc2019/416/)s is that they can bundle both either dynamic frameworks or static libraries, for multiple architectures and destinations, while keeping slices separate (Check Info.plist) - which is not the case for fat libraries.

In this post I share recent learnings on how to use `xcodebuild` and `lipo` to create `XCFrameworks`, specifically from a static library.

## Content
- `SampleStaticLib/` has an `.xcodeproj` containing a static Swift library.
- `StaticXCFrameworkSampleApp/` has a sample app that consumes the generated `XCFramework`. 
- `derived_data` is a custom derived data path
- `archives` is where built archives are stored. Note that there are two `_iphonesimulator` archives that are different (yet similar) slices that are seggregated to be lately combined into a single `.a`

## Steps

### Archive `SampleStaticLib` for each arch and sdk
```swift
xcodebuild archive \
-scheme SampleStaticLib \
-derivedDataPath derived_data \ // custom derived data path
-arch arm64 \
-sdk iphonesimulator \
-archivePath archives/arm64_iphonesimulator
ONLY_ACTIVE_ARCH=NO \
OTHER_CFLAGS="-fembed-bitcode" \ // enable bitcode
DEFINE_MODULE=YES \ // ensures .swiftmodule is correctly built
```
The above command should be run multiple times for the following variations to ensure the static library is built for the all desired combinations of architectures and destinations:
- arm64 / iphoneos
- arm64 / iphonesimulator
- x86_64 / iphonesimulator

The copy argument on line 24 is to be replaced by the following on each run to ensure each `.a` slice is added to a different folder:
- `cp -r derived_data/Build/Products/Debug-iphoneos/ tmp_built_products/arm64_iphoneos`
- `cp -r derived_data/Build/Products/Debug-iphonesimulator/ tmp_built_products/arm64_iphonesimulator`
- `cp -r derived_data/Build/Products/Debug-iphonesimulator/ tmp_built_products/x86_64_iphonesimulator`

> As result `archives/` will contain the build products for each combination
### 1. Generate a fat file for iphonesimulator slices
Both slices generated for the iphonesimulator have to be combined into a fat file to avoid the folowing issue when generating an XCFramework:

> Both 'ios-x86_64-simulator' and 'ios-arm64-simulator' represent two equivalent library definitions.
For that [lipo](https://www.manpagez.com/man/1/lipo/) can be used: 
```swift
lipo -create \
tmp_built_products/arm64_iphonesimulator/libSampleStaticLib.a \
tmp_built_products/x86_64/libSampleStaticLib.a \
-o tmp_built_products/combined_iphonesimulator/libSampleStaticLib.a
```

### 2. Verify built files
Before leading to the final step let's confirm if the iphonesimulator slices were combined into a fat file and if the iphoneos slice looks correct.

For that you can use [lipo](https://www.manpagez.com/man/1/lipo/):
```swift
lipo tmp_built_products/combined_iphonesimulator/libSampleStaticLib.a -info
```

Which should print the following for `tmp_built_products/combined_iphonesimulator/libSampleStaticLib.a`:
> Architectures in the fat file: tmp_built_products/combined_iphonesimulator/libSampleStaticLib.a are: x86_64 arm64 
and
> Non-fat file: tmp_built_products/arm64_iphoneos/libSampleStaticLib.a is architecture: arm64
for the iphoneos slice.

### 3. Create the XCFramework
xcodebuild comes with a command that allows creating an `XCFramework` from different slices of a library or framework.
In this case, let's see how to generate one from `SampleStaticLib` slices built on `tmp_built_products/` in the previous step

```swift
xcodebuild -create-xcframework \
-library tmp_built_products/arm64_iphoneos/libSampleStaticLib.a \
-library tmp_built_products/combined_iphonesimulator/libSampleStaticLib.a \
-headers tmp_built_products/arm64_iphoneos/SampleStaticLib.swiftmodule \
-output SampleStaticLib.xcframework
```

Note that the `.swiftmodule` of one of the slices is passed as header, which allows jumping into the public interface of the library in Xcode.
A `.swiftmodule` is a bibnary/AST representation of the public API.
